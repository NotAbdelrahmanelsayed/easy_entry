## Key Learnings

- **Per-row child-table actions** in easy_entry use a Custom Button field (`fieldtype: Button`, `in_list_view: 1`, `columns: 1`, `print_hide: 1`) handled via `frappe.ui.form.on("<Child Doctype>", "fieldname", fn)`. The handler receives `(frm, cdt, cdn)` and reads the row with `locals[cdt][cdn]`. Custom fields ship via `easy_entry/fixtures/custom_field.json`; the fixtures list in hooks.py uses `{"dt": "Custom Field", "filters": [["name", "like", "%-ee_%"]]}`.
- **Daily report recipients** are role-derived, not a stored list. Both scheduler tasks (`tasks/daily_owner_report.py` → Store Owner; `tasks/ar_summary_email.py` → Store Owner/Accounts Manager/Accounts User) go through `tasks/recipients.py:get_report_recipients(roles)`. To silence one address without stripping roles the user needs for permissions, add it to the site_config list `easy_entry_report_optout` (`bench set-config -p easy_entry_report_optout '["a@b.com"]'`). Opt-out matching is case-insensitive.
- **Restarting workers on this bench:** `bench restart` fails — supervisor runs as root and `sudo` needs a password the agent can't supply. The user must run it. Prefer `sudo supervisorctl restart frappe-bench-workers:` (scheduler + short/long workers) over a full restart: it reloads Python for scheduled jobs without interrupting the live POS/web users in the `frappe-bench-web` group.
- **Configurable settings** for the app are stored on existing ERPNext singletons (e.g., Stock Settings) via Custom Field fixtures — no new Singleton DocType needed. Reads use `frappe.db.get_single_value("Stock Settings", "fieldname")`.
- **Project:** easy_entry
- **Description:** Add Items, Prices, Stock and Purchase invoices with ease in a single DocType
- The app is NOT installed on a dedicated site; local testing uses the `capital` site (has ERPNext). Dev web server runs on port 8002 — `http://capital:8002`.
- The Item Manager SPA lives in `frontend/` (Vue 3 + Vite + frappe-ui). Build with `cd frontend && npm run build`; it writes `easy_entry/www/item-manager.html` and assets to `public/frontend/`. Served at `/item-manager`.
- Stock Reconciliation's "Difference Account" field is named `expense_account` (not `difference_account`). For opening-stock items it must be an Asset/Liability account — use the company's "Temporary Opening" account.
- The Barcode Generator singleton needs `prefix` configured, otherwise every new Item insert fails with "Prefix is required" (the `Item.after_insert` hook calls it).
- **Print Format `css` field** is injected as a separate `<style>` block after the inline HTML `<style>`. For label formats, leave `css: ""` and put ALL styles inside the `html` field only. The old `50 * 25` had `direction:rtl` in `css` which broke English items and `font-size:13px` that overrode the intended 8pt.
- **SVG `height: 100%` inside a flex item collapses to 0 in old WebKit** (wkhtmltopdf). The barcode was completely invisible in the old format for this reason. Always use explicit `height: NNmm` on `.barcode svg`.
- **wkhtmltoimage ≠ wkhtmltopdf** for label testing: `wkhtmltoimage` ignores `pdfkit-page-height` meta tags and renders natural content height. Screenshots show extra whitespace below the barcode. The real PDF (wkhtmltopdf) correctly clips to the declared page height. Verify label designs in Frappe's actual printview.
- **Extra query params on `/printview` are fragile transport**: the printview "Get PDF" button rebuilds the URL with only doctype/name/format/letterhead, dropping custom params like `supplier_code`. Never rely on a URL param as the ONLY source for data a print format needs — give the template a server-side fallback (jinja method hook). Pattern: `{%- set x = frappe.form_dict.get('param','') or my_jinja_helper(doc.name) %}`.
- **Thermal label printers are 1-bit**: mid-gray text (e.g. `color: #555`) at 6pt dithers to near-invisible dots on the physical label. Always use pure black (`#000`) for anything that must be legible on a printed label.
- **Supplier codes** (`ee_supplier_code`): 3 random uppercase letters from A-Z minus I/O (confusable with 1/0), generated on Supplier `after_insert`; labels fall back to the item's first Item Supplier row via the `item_supplier_code` jinja method when no `supplier_code` param is passed.
- **In `bench console` (piped input)**, top-level imports don't survive into later statements reliably; jinja env (`frappe.local.jenv`) caches the `form_dict` reference at first render — set `frappe.local.jenv = None` between renders when testing print formats with different `form_dict` values. Run multi-statement test scripts via `exec(open('/tmp/x.py').read(), {})`.
- **`exec(open(...).read())` in bench console uses split globals/locals** → functions defined in the script can't see module-level names (NameError on free vars inside callbacks). Bind needed values as default args, e.g. `def cb(*a, _x=val, _real=frappe.sendmail, **k): ...`.
- **Auto-reorder Material Requests never close in this shop's workflow.** Stock is restocked via Stock Reconciliation / Stock Count (Item Manager `set_item_qty`, EE Stock Count), NOT via Purchase Order → Purchase Receipt. So `Material Request Item.received_qty` stays 0 and MR `status` stays `Pending` indefinitely. Any logic that treats an open MR (`received_qty < qty`) as "still needed" produces permanent false positives. The reliable "still short" signal is **live stock vs reorder level**: `COALESCE(Bin.actual_qty,0) <= Item Reorder.warehouse_reorder_level` (joined on item+warehouse). Reorder level/qty live on the `Item Reorder` child table (`warehouse_reorder_level`, `warehouse_reorder_qty`), NOT on `tabBin` (Bin has no `reorder_level` column).
- **`tabEmail Queue` has no `subject` column** in this version; the subject is embedded in the MIME `message` body. `now=True` on `frappe.sendmail` sends synchronously (raises on SMTP failure) and still records an Email Queue row with `status='Sent'`.
- **Attach a generated PDF to an email** via `frappe.sendmail(attachments=[{"fname": "x.pdf", "fcontent": pdf_bytes}])`; build bytes with `from frappe.utils.pdf import get_pdf; get_pdf(html)` (wkhtmltopdf engine). Reorder email does this (`reorder_item_pdf.html` template → `get_pdf` → attachment), with a yellow 📎 banner in the email body so the attachment is visible.
- **Code overrides that are monkeypatches in `easy_entry/__init__.py` do NOT take effect in already-running workers.** The Arabic+PDF reorder override is wired by `easy_entry/__init__.py` repointing `erpnext.stock.reorder_item.send_email_notification`. This only applies when the *current* `easy_entry` package is imported. The supervisor scheduler/workers (group `frappe-bench-workers`: schedule + short-worker + long-worker) are long-lived RQ processes that hold modules in memory and never re-import changed `.py` files. So after ANY Python change under `easy_entry/`, you MUST restart workers or scheduled jobs (daily reorder/owner-report emails) keep running the OLD code. Symptom of a stale worker: the reorder email arrives with ERPNext's DEFAULT subject `طلبات الشراء التلقائية - تم الإنشاء` (= "Auto Material Requests Generated") and no PDF, instead of the override's `أصناف تحتاج إعادة طلب (N)`. Fix: `sudo supervisorctl restart frappe-bench-workers:` (reloads only workers+scheduler, leaves web/redis untouched) or `bench restart`. See bug-035.
- **Arabic in wkhtmltopdf/get_pdf renders correctly** ONLY if the HTML is a full document with `<meta charset="utf-8">` and `dir="rtl"`; letters shape/connect fine. When previewing an email *fragment* (no `<head>`) with `wkhtmltoimage`, pass `--encoding utf-8` or you get latin-1 mojibake — a preview artifact only; real emails set charset via MIME headers. No pdf rasterizer (poppler/pdftoppm) on this box — preview PDF HTML via `wkhtmltoimage` (same WebKit engine) instead of reading the .pdf.
- **This bench's supervisor groups**: `frappe-bench-web` = the HTTP-serving gunicorn (`--preload`, 9 workers) + node-socketio — restart this one (`sudo supervisorctl restart frappe-bench-web:`) after editing any Python module that a live web request already imported (edits to a brand-new file work immediately since Python imports it fresh on first request; edits to an already-imported module don't take effect until the worker process restarts). `frappe-bench-workers` = schedule + short/long RQ workers, for background jobs/scheduled emails only — a different group, restarting one does not refresh the other. Neither restart works without a password-protected `sudo`, which the agent cannot supply — the human must run it.
- **Creating a test `Sales Invoice` on this bench requires `si.is_pos = 0` explicitly** — pos_next's `validate_pos_paid_amount` override rejects submission with "At least one mode of payment is required for POS invoice." if `is_pos` defaults truthy (likely a POS Profile default) and no `payments` rows are set.
- **Never trust `wkhtmltoimage` for pixel-accurate mm-layout verification, even with `--zoom`/`--width`.** It doesn't understand `pdfkit-page-width`/height meta tags the way `wkhtmltopdf` does, and CSS `mm` units don't map to the same physical scale — a `width:36mm` div can render at a wildly different fraction of its container than `wkhtmltopdf` would produce. For label print formats always render the real PDF and rasterize that (`wkhtmltopdf` → PDF → `PyMuPDF`/`fitz` `page.get_pixmap()`, no poppler/pdftoppm on this box — `pip install PyMuPDF` works standalone). See bug-038.
- **`wkhtmltopdf`'s default "smart shrinking" makes the pixel/DPI ratio non-constant** and visibly distorts `mm`-based CSS layouts (elements render narrower/shifted than declared). Frappe's own `frappe.utils.pdf.get_pdf()` already passes `--disable-smart-shrinking` for wkhtmltopdf > 0.12.3 (this bench: 0.12.6.1), so production PDFs are unaffected — but any manual/ad-hoc `wkhtmltopdf` invocation for testing MUST include `--disable-smart-shrinking --disable-javascript --disable-local-file-access` to match production, or the render is not representative. See bug-038.
- **`code128_svg()` (`easy_entry/utils/barcode.py`) generates rects directly in mm units** with `viewBox="0 0 {width_mm} {height_mm}"` — the viewBox aspect ratio must always exactly equal the physical `width_mm:height_mm` ratio. Do NOT go back to a module-unit viewBox (e.g. `0 0 total_w 100`) relying on `preserveAspectRatio="none"` to stretch it — that reintroduces the left-gap bug (bug-038) because `preserveAspectRatio="none"` isn't reliably honored by wkhtmltopdf's WebKit when combined with CSS `width:100%` overriding an explicit mm attribute.

- **Testing on this bench requires `bench --site <site> set-config allow_tests true`** first (it's a production site, off by default) — remember to set it back to `false` after `run-tests` finishes. `IntegrationTestCase` tests here run against the live `erp.abderlahman-erp.store` site (no separate test site exists); self-cleaning teardown (delete test Users/Items/etc.) is mandatory.
- **`bench execute` prints a spurious `NameError: name '<app>' is not defined`** after any traceback from `frappe.throw`/exceptions raised inside the called method — this is bench-cli's own exception-cleanup quirk, not a real error. Read the actual traceback above it (ends in the real exception class, e.g. `frappe.exceptions.ValidationError: ...`) rather than trusting the last line/`tail`.
- **frappe-ui 0.1.261 `AxisChart`**: `config.series[].name` doubles as BOTH the legend label and the key used to pull each point's y-value out of `config.data` rows (`row[series.name]`); `config.xAxis.key` is the row key for x. So translated/localized series names must be applied consistently to both the `series` array and the data-row keys — build them from one shared constant, don't mutate the resource's own data in a `watch()` (redundant re-runs will double-transform and silently produce `NaN`). `xAxis: {type: "time", timeGrain: "day"}` accepts plain `"YYYY-MM-DD"` date strings.
- **Owner Dashboard refresh data flow**: period KPIs/best sellers come from the `dashboard` frappe-ui resource, while trends, weekday performance, receivables, and low stock come from `staticData`. An in-place full refresh must reload both resources; keeping period/date/sort/item filters in independent Vue refs preserves them automatically. Use a combined loading computed to disable the control whenever either request is active.
- **frappe-visual-reviewer skill's `--routes` works for any app route**, not just `/app/...` Desk pages — pass SPA paths like `/easy/owner-dashboard` directly, and `--user <email>` to screenshot as a specific (e.g. deliberately unprivileged) user for permission-state QC. For ad-hoc network/console debugging beyond what the skill's report.json gives (e.g. finding the URL behind a generic "Failed to load resource: 404" console message), a raw Playwright script must live *inside* `.claude/skills/frappe-visual-reviewer/` (or `cd` there) so Node's ESM resolver finds the skill's local `playwright-core` — running it from an arbitrary cwd/tmp path fails with `ERR_MODULE_NOT_FOUND`.
